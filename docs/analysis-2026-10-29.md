# chaoxing-auto-study 项目评估与再开发建议

- 评估日期：2026-10-29
- 评估对象：本地开发副本 `temp_20261028_02/chaoxing-auto-study` + GitHub `LyricQing/chaoxing-auto-study`
- 评估方式：全量阅读 4 个文档、核对 git 历史与远端状态、交叉验证字体反爬机制与同类方案

---

## 0. 一句话结论

这**不是一个代码项目**，而是一份约 220 行的操作手册——用大模型的视觉能力和鼠标坐标，去模拟一个人上课。

它在"跑通一次"的意义上是成功的，但**执行层选错了**：把本来就在 DOM 里的结构化信息，绕道像素和坐标去取用。因此它的主要缺陷不是"还没调好"，而是"在这一层调不好"；换成 DOM 层，大部分缺陷会自然消失。

好消息是：目标本身完全可达，路径成熟，重构范围可控——**需要换执行内核，不需要从零重写产品**。

答案是否定的。它有明确的状态机、明确的输入输出、明确的判定条件——这是一个典型的自动化程序，被写成了一份让大模型即兴表演的剧本。

## 2. 当前执行链路复原

```
页面 DOM
  └─(1) 无障碍树文本 + 截图        get_app_state
        └─(2) agent 读树/读图判断   LLM 推理
              └─(3) 点击/按键/滚动  click(element_id) | click(x,y) | press_key | scroll
                    └─(4) 状态判定  文本含「任务点已完成」「音频正在播放」「满分」「答题卡」
                          └─(5) 下一节
```

四个关键机制，及各自的代价：

| 机制 | 能力 | 代价 |
|---|---|---|
| 无障碍树 | 目录项、章节测验胶囊、播放器文档都有稳定 `element_id`，可免截图点击 | **题干文本是字体混淆后的假字符**（「甲午海战」→「懪午懮战」），语义已丢失 |
| 截图 + VLM | 唯一能读题的通路 | 3–6 s/张；读数有概率误差；无法复用 |
| 坐标点击 | 能点到树上没有的元素（选项圆圈、提交、下一节） | 耦合「窗口尺寸 × DPI × 浏览器缩放 × 滚动位置」四元组 |
| 焦点依赖 | 规避平台的前台检测 | Edge 必须前台且不最小化；未聚焦时点击**静默失效**（不报错、无效果） |

## 3. 整体评价

### 3.1 做对的部分（应原样保留）

1. **接入方式克制**——用用户真实已登录的浏览器，不新开实例、不接管 CDP、不伪造 UA、不 kill 进程。这是全项目最有价值的决策：它把网络层与设备指纹层的检测面压到了理论最低。
2. **不绕过服务端判定**——等「任务点已完成」而不是伪造进度上报。避开了"前端显示完成、后台不计学时"这类典型翻车。
3. **经验沉淀扎实**——坑表、坐标标定、ESC 语义、Exec 时长上限，全部来自真实失败，不是想象出来的。这类一手知识很难得，是重构时最该继承的资产。
4. **可读性高**——结构清晰、命令给全、故障有对应处置，下一个人（或下一个 agent）能直接接手。
5. **有自检习惯**——`docs/chaoxing-skill-six-fixes.md` 把 6 个问题逐条映射到改法并附验收标准。这种工程习惯比代码本身更值钱。

### 3.2 但"成功"是有条件的

它跑通的是**一门课、一个窗口尺寸、一个缩放比例、一个浏览器**。换分辨率、换课程 UI、换题型，参数全部失效。

这不是"泛化不足"，是**没有泛化机制**——所有适配都发生在文档里，靠人重写。一份需要"每次现场标定坐标"的自动化，本质上仍是半自动。

## 4. 主要问题

### 4.1 结构性缺陷（改文档无法消除）

#### S1 观测通道错配：用像素去读结构化的文本

题干原本就是 DOM 里的字符串，只是被 `font-cxsecret` 用自定义字体把码位映射成了假字符。**这个映射是可逆的**：

```
style#cxSecretStyle → @font-face src:url("data:application/font-ttf;base64,...")
  → 解 base64 得 TTF → 解析 cmap / glyf
  → glyphToPath → JSON.stringify → MD5 → 取第 25~32 位作为 key
  → 查「glyph 哈希 → 真实 Unicode」表 → 逐字符替换
```

社区已有多个可用实现，第三方实测覆盖 8 份不同章节测验、未知字符 0，且确认"每页字体不同、不能写死映射、同一套代码跨页有效"。

现状选择"截图用眼睛读"，等于主动放弃确定性信息，改用概率性视觉推断。代价不是"慢"，而是**确定性丢分**，且已经发生两次：

- 1.20 Q1 判断题答错（正确答案「对」）；
- 1.22 Q1 把 C 点成 D，丢 33.3 分。

两次都不可挽回（只允许作答一次）。

#### S2 控制通道错配：用坐标表达意图

`clickAt(161, y)` 把"点第 3 个选项"降维成"点屏幕上的某个像素"。文档为此维护了三套坐标系：

| 缩放 | 圆圈 x | 行距 | 提交 | 确认 |
|---|---:|---:|---|---|
| 100% | ≈161 | — | (590,550) | (780,440) |
| 80% | ≈131 | 40 px | 未标定 | 未标定 |
| 50% | ≈76 | 28 px | (566,623) | (713,393) |

并明确记录了失败模式："偏 ±8 px 就落到相邻选项"。

在**写操作不可逆**的场景里，这是不可接受的：

- 点空 → 不报错
- 点偏 → 不报错
- 点完页面自动滚动 → 后续坐标全部失效，不报错

**三种都是静默失败。** 正确表达应是 `li[qid="123"].click()` 然后断言 `input[name="answer123"].value` 已变——语义定位 + 结果校验，与像素无关。

#### S3 状态无处存放：进度写在 Markdown 里

当前进度是 `HANDOFF.md` 的一段人话（"已完成到 3.5 的视频，3.5 测验待做"），答案表是 `SKILL.md` 的一张表。后果：

- 换课程 = 重写文档；
- 断点续跑 = 靠人读文档回忆；
- **幂等性不存在**。已经翻车一次：点右侧目录跳节，导致 1.20 测验永久漏做。
- **数据污染技能本体**：5 道题的答案写进了通用技能文件，任何人 clone 下来都带着你的课程数据。

#### S4 执行模型与任务形态错配

任务形态是"数小时挂机"，执行模型是"单次 Exec ≤60 s + agent 轮次"。于是一条长流水线被切成上百次 LLM 往返：每次都带上下文、每次都可能被 ESC / 超时 / 焦点丢失打断、每次都要重新确认状态。

"20 秒/节"这个 KPI 就是为这个错配打的补丁，而且**它优化的是错误的量**：

- 一节课视频几十分钟，把节间切换从 20 s 压到 2 s，20 节也只省 6 分钟；
- 真正的收益应该是"不用人守着"和"不会答错"。

用 20 秒目标去驱动设计，会系统性地把工程推向"牺牲校验换速度"——下面这条正好印证。

### 4.2 三条"硬规则"其实是三个缺失能力的补丁

这是我认为最值得指出的一点。`SKILL.md` 开篇的三条硬规则，每一条都在补偿一个架构缺陷：

| 硬规则 | 在补什么 | 换到 DOM 层后 |
|---|---|---|
| 弹窗出现立即确认，不截图、不思考、不复核 | 没有提交前校验能力，只能赌坐标点对了 | 提交前遍历 `input[name^="answer"]` 断言全非空，再确认。**规则可删** |
| 对错一律不复盘，不读分数、不看绿勾 | 没有反馈闭环，读了也用不上 | 成绩页不混淆、可读，可把"我的答案 vs 正确答案"回写题库。**规则可删** |
| 禁止点右侧目录，只能线性前进 | 无法判断某节测验是否已做，只能靠顺序规避 | 目录项本身带完成状态，可按状态幂等导航。**规则可删** |

而且这三条规则**造成过实际损失**：硬规则 1"不犹豫"的直接后果，就是 1.22 那次点偏被立即确认、33.3 分不可挽回。

> **规则越多，说明系统越不知道自己在哪里、在做什么。** 用提示词约束行为，等于把状态机的职责外包给了 LLM。

### 4.3 工程质量问题

| # | 问题 | 具体表现 |
|---|---|---|
| E1 | 文档即程序 | 改一个坐标 = 改自然语言；不可测试、不可 lint、不可回滚 |
| E2 | 四处描述漂移 | 缩放默认值：SKILL「默认 80%」vs README「默认 100%，题多时 80%」vs docs「F11 + 两档 ≈80%」；提交坐标：正文 (590,550) vs 50% 段 (566,623)；窗口高度：SKILL 1280×672 vs HANDOFF 1280×720 |
| E3 | 标定不可复现 | 坐标"现场标定一次"写回文档，但不记录 DPR / 缩放 / 窗口，下次环境一变就失效 |
| E4 | 无 LICENSE | 公开仓库但无许可证 = 默认保留所有权利，他人无法合法复用 |
| E5 | 文档重复 | `.trae/documents/` 与 `docs/` 存了同一份设计稿（已 diff 确认完全一致），双份必然漂移 |
| E6 | 无动作断言 | 所有操作"发出即认为成功"，没有"动作后校验"。这是 E 类里最危险的一条 |
| E7 | 伪代码脆弱 | 如 `/list-item "章节测验"[^i]*? id=(\d+)/`：`[^i]*` 排除了字母 i，中间只要插入含 i 的属性（index/clickable/invisible）就匹配失败 |

### 4.4 安全与合规

| # | 风险 | 说明 |
|---|---|---|
| C1 | **公开仓库泄露运行态数据** | `HANDOFF.md` 含完整课程 URL（`chapterId / courseId / clazzid / cpi / enc`）、做题进度、答案表。本地第 4 次提交**尚未推送**——推送前必须脱敏，否则等同公开账号上下文 |
| C2 | 平台协议风险 | 学习通用户协议禁止自动化模拟；已知处置包括进度不计入、强制人机校验、临时冻结。这类风险**不会因为技术更优雅而消失** |
| C3 | 学术诚信边界 | 章节测验属过程性考核。建议明确边界：只用于自己已选课程、不接考试、不改倍速、不代刷他人账号 |
| C4 | 静默失败 → 假完成 | 坐标点空导致漏答，用户以为刷完，实际提交空卷或未提交。**这比报错更糟** |

## 5. 关键判定：缺陷能否规避

### 5.1 四层接入方案对比

| 维度 | L0 OS 级 computer-use（现状） | **L1 浏览器内 DOM（扩展/用户脚本）** | L2 CDP（Playwright 持久化上下文） | L3 协议级 HTTP |
|---|---|---|---|---|
| 读题 | 截图 + VLM，3–6 s/题，有误差 | DOM 文本 + 字体解码，明文，<100 ms | 同 L1 | 接口返回，需处理加密字段 |
| 作答 | 坐标点击，随缩放漂移 | 元素 click + 断言 | 同 L1 | 构造请求 |
| 稳定性 | 低（四元组耦合） | 高 | 高 | 中（接口/参数会变） |
| 节间速度 | 13–20 s | 2–4 s | 2–4 s | < 1 s |
| 前台占用 | 必需，且不能最小化 | 不需要 | 不需要 | 不需要 |
| 检测面 | 网络层最低，行为层有合成点击特征 | 网络层最低，行为层为 DOM 事件 | 网络层同，另有 `navigator.webdriver` 等需处理 | 网络层最高，心跳/时序易断层 |
| 开发成本 | 已投入，但每次适配靠人 | 中（一次性 600–900 行） | 中 | 中高（逆向 + 签名） |
| 与"不接管调试端口"约束 | 符合 | 符合 | **冲突** | 冲突 |
| 合规风险 | 中 | 中 | 中高 | 高 |

### 5.2 结论

**在 L0 这一层上，缺陷不可规避。** 三个理由都是硬的：

1. 字体混淆让无障碍树丢失字形语义，视觉读数无法保证确定性；
2. 坐标到元素的映射依赖四个连续变量，参数空间不封闭，无法穷举标定；
3. 串行 Exec + 前台独占，使数小时任务在工程上不可持续。

**在项目目标上，缺陷可以规避。** 信息本来就在 DOM 里、映射可逆、动作可按语义定位。所以这不是"问题无解"，是"解在另一层"。

**因此：不需要从零重写产品，需要替换执行内核。** 保留技能外壳、接入约束、经验知识；替换观测 / 控制 / 状态三件套。按逻辑量估算约 70% 被替换，30%（约束、流程、答案数据）可复用。

**不建议走 L3。** 它最快，但把检测面从行为层推到网络层，且需持续逆向签名参数，维护成本随平台更新线性上升。对"一个人、几门课"的使用强度不划算。

**不建议 L2 作主线。** 与既有"不接管调试端口"约束冲突，且需处理 webdriver 指纹。可作**回归测试与批量模式**的旁路。

> **推荐主线：L1。**

## 6. 目标架构

```
┌──────────────────────── 浏览器扩展 / 用户脚本（MV3） ────────────────────────┐
│  frame-locator      studentstudy → iframe#knowledge/cards → work → frame_content │
│  text-decoder       style#cxSecretStyle → base64 TTF → cmap/glyf → 明文          │
│                     status: plain | decoded | partial | unsupported              │
│  question-extractor div.questionLi → {qid, type, stem, options[], selected}      │
│  filler             li[qid].click() → 断言 input[name="answer<qid>"] → 提交       │
│  video-keeper       监听 pause 自动续播；不使用倍速                               │
│  progress-store     progress.json / SQLite：章节状态、答案、得分                  │
│  audit-log          每题原文/答案/置信度/结果，可回溯                             │
└──────────────────────────────────┬──────────────────────────────────────────┘
                                   │ 仅在异常时请求
┌──────────────────────────────────▼──────────────────────────────────────────┐
│  本地答题服务（Node / Python）                                                │
│  题库检索（题干指纹） → 命中直出；未命中 → LLM 文本作答（非图像）              │
│  低置信度 → 挂起等人工确认                                                    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 三条设计原则

1. **动作必须可断言**——每个写操作后校验状态，失败即停，不猜。
2. **状态必须落盘**——任何时刻可从磁盘恢复；重复执行不产生副作用（幂等）。
3. **agent 退出执行环**——扩展自主运行，agent 只在异常（未知题型、提交失败、人工确认）时介入。这一条把"上百次 LLM 往返"压成"1 次启动 + 少量异常处理"。

## 7. 重构可行性与风险

### 7.1 三个必须先验证的假设（Phase 0，约 1–2 小时）

| # | 假设 | 验证方法 | 不成立的后果 |
|---|---|---|---|
| A | 页面内可读到 `style#cxSecretStyle` 并解出明文 | 控制台注入约 30 行脚本，打印解出的题干 | 退回"截图读题"，但保留元素点击，收益减半 |
| B | `li[qid].click()` 能触发 `addChoice` 并写入 input | 控制台点击后读 `input.value` | 改用 `dispatchEvent` 或直接赋值，成本略升 |
| C | 后台标签页视频仍计时（或 pause 后自动 play 可维持） | 切到其他标签 2 分钟，观察任务点 | 退化为"专用窗口挂机"，仍不需 agent 轮次，但非完全无人值守 |

**C 是最大不确定性。** 若 C 不成立，"后台挂机"变成"专用窗口挂机"——仍是巨大改善（不占鼠标、不耗 LLM 轮次），但不是完全无人值守。

### 7.2 其他风险与缓解

| 风险 | 缓解 |
|---|---|
| 平台 UI 改版导致选择器失效 | 选择器集中在单个 adapter 文件，用 DOM 结构 + 文本双特征定位 |
| 字体映射表未覆盖新字 → 部分乱码 | `status=partial` 时降级到截图或挂起人工，**不静默猜** |
| 扩展被识别 | 概率低但存在：不暴露 `chrome.runtime`、注入最小化、不挂全局变量 |
| 合规风险 | 无法消除，只能收敛使用范围 |

## 8. 再开发方向（按性价比排序）

### P0 —— 不重构也应立即做

| # | 事项 | 收益 |
|---|---|---|
| 1 | **提交前断言**：遍历 `input[name^="answer"]`，有空则逐题补点，绝不"不犹豫" | 直接消除丢分主因 |
| 2 | **提交后读成绩页**，回写"我的答案 vs 正确答案" | 让答案表变成可增长题库，形成监督信号 |
| 3 | HANDOFF.md 脱敏 + 补 `.gitignore`，推送前处理 | 消除 C1 |
| 4 | README / SKILL / docs 合并为单一事实源，删掉已证伪的 50% 方案 | 消除 E2、E5 |

### P1 —— 换内核
